# 페어링 오류 표시 수정 독립 검토

검토일: 2026-10-22. iPhone에서 연결 버튼을 눌러도 반응이나 오류가 보이지 않는 보고와, 공개 API 기록의 401·반복 429를 기준으로 `apps/web/src/App.tsx`, `api.ts`, `styles.css`, `pairing.test.ts`의 최종 수정본을 구현자와 별도로 검토했다.

## 판정

**Axis A와 B 모두 미해결 BLOCKER·IMPORTANT 없음.** 오류를 입력칸과 연결 버튼 사이에 표시하고 자동으로 화면 안으로 가져와, 기존 상단 공통 알림이 키보드 위 화면 밖에 놓이던 문제를 직접 다룬다. 390×660 PC 브라우저 모의 429 화면 `output/playwright/pairing-rate-limit-390.png`를 별도로 열어 한국어 오류와 다시 시도 버튼이 함께 보이는 것을 확인했다. 실제 iPhone Safari 동작은 아직 사용자가 재확인해야 한다.

## Axis A — 동작·접근성·보안

- 전송 중에는 버튼 문구가 `연결 중…`으로 바뀌고 비활성화된다. 별도 ref가 같은 렌더 주기 안의 중복 제출도 막는다. 실패 뒤 ref와 버튼 상태를 되돌려 재시도할 수 있다.
- 잘못되거나 만료·재사용된 코드(401), 10분 시도 제한(429), 형식 오류(422), 15초 응답 지연을 한국어로 구별한다. 지연은 `AbortController`와 해제되는 타이머로 처리하며 재시도 때 코드가 이미 소비됐을 가능성을 설명한다.
- 입력에는 `aria-invalid`·`aria-describedby`, 오류에는 `role="alert"`를 적용했다. 오류가 입력과 버튼 사이에 있고 표시될 때 `scrollIntoView`를 호출하므로 좁은 화면에서도 가까운 위치에 보인다. 페어링 서버의 인증·속도 제한은 바꾸지 않았다.

## Axis B — 코드베이스 적합성

- 오류 매핑과 요청 시간 제한은 기존 API 모듈에, 폼 상태와 표시 위치는 기존 PairCard에 넣었다. 추가 의존성이나 별도 인증 경로가 없다. 스타일은 기존 danger notice의 간격과 글자 크기만 조정한다.
- 검사들은 상태별 문구, 15초 중단, 429 전달을 확인한다. DOM 스크롤 동작은 단위 검사로 주장하지 않고 좁은 화면 브라우저 캡처로 확인했다.

## 독립 검증

- `npm run build --prefix apps/web`: 성공.
- `npm test --prefix apps/web -- --run`: **16 passed**.
- `output/playwright/pairing-rate-limit-390.png`: PC 브라우저 모의 429, 390×660 화면에서 오류와 버튼 표시 확인. 실제 공개 API를 통한 새 코드 페어링과 iPhone Safari는 이 검토에서 실행하지 않았다.
